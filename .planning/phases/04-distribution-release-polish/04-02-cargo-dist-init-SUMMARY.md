## Decisions Made

- **cargo-dist 0.32 writes config to `dist-workspace.toml [dist]`, not `Cargo.toml [workspace.metadata.dist]` — for single-crate repos.** This is Assumption A1 in RESEARCH (rated LOW risk) and it materialised here. The RESEARCH `<recommendation>` to use `[workspace.metadata.dist]` reflects the older cargo-dist behavior; 0.32 defaults to the standalone TOML file. Functionally equivalent — all D-79 keys land in the same `[dist]` section, just at a different file path. The `dist-workspace.toml` file is in-repo (tracked by git, included in the crate tarball). Plan 04-03 (Wave 3) reads from `dist-workspace.toml`, not from Cargo.toml.
- **cargo-dist 0.32 binary name is `dist`, not `cargo-dist`.** `cargo install cargo-dist` produces `~/.cargo/bin/dist`. No `cargo dist` subcommand is registered. The plan's verification command `cargo dist --version` does NOT work on this version. The correct invocation is `dist --version` (or `/home/chasel/.cargo/bin/dist --version` in environments where `~/.cargo/bin` is not on PATH). Documented in this Summary and in 04-02-DRY-RUN.md so Wave 3 / future plans know.
- **Manual config patch is required after `dist init`** because `dist init --yes` flags do NOT include `--tap`, `--pr-run-mode`, `--formula`, or `--publish-jobs`. The workflow is: `dist init --yes <flags>` → manually edit `dist-workspace.toml` to add the missing keys → `dist generate` to re-emit `release.yml` against the patched config. The plan's fallback command `cargo dist init --yes --tap=…` was theoretical; cargo-dist 0.32 does not expose these as CLI flags.
- **Added `homepage` field to Cargo.toml** — same URL as `repository` (D-77 contract). cargo-dist requires a homepage for Homebrew formula generation; the warning from `dist init` made this an effective Rule 2 (auto-add missing critical functionality) blocker for the publish-homebrew-formula job. Adding the field has zero negative side-effects: it's a valid `[package]` field per crates.io spec; `cargo publish --dry-run` still clean.
- **Plan's verification grep gates needed semantic re-interpretation** — `dist plan` output uses `installer.sh` (not `shell`) and `installer.ps1` (not `powershell`), and `ahb.rb` (not `Formula/ahb.rb`). The semantic check is fully satisfied (shell installer present, PowerShell installer present, brew formula `ahb` confirmed) — the plan's grep substrings reflected an older cargo-dist version's output verbiage. Documented in 04-02-DRY-RUN.md § 2 "Notes vs. plan acceptance text".
