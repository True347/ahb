<verified_codex_rollout_schema>
<!-- From RESEARCH §Codex JSONL Schema (verified against openai/codex issue #14728). -->

`~/.codex/sessions/YYYY/MM/DD/rollout-{TIMESTAMP}-{UUID}.jsonl` — each line is a RolloutLine.

Relevant variant (we ignore all others):
```
{
  "timestamp": "<RFC3339>",      // RolloutLine.timestamp (outer)
  "type": "event_msg",
  "payload": {
    "type": "token_count",
    "info": null,                  // we do NOT read .info (D-47 — no estimation)
    "rate_limits": {               // null is widespread bug per issue #14880
      "primary":   { "used_percent": 0.0, "window_minutes": 299,    "resets_in_seconds": 17940 },
      "secondary": { "used_percent": 6.0, "window_minutes": 10079,  "resets_in_seconds": 275281 }
    }
  }
}
```

Conversion rules:
- `HpWindow.label` = `Cow::Borrowed("primary")` / `Cow::Borrowed("secondary")` (passthrough literal, D-48). Phase 2 emits at MOST 2 windows per codex row.
- `HpWindow.percent_remaining` = `(100.0 - used_percent as f32).clamp(0.0, 100.0)` — note Codex emits *used* percent; AHB renders *remaining*.
- `HpWindow.reset.resets_at` = `line.timestamp + Span::new().seconds(resets_in_seconds as i64)` — **anchor on the rollout line's own timestamp, NOT ctx.now** (RESEARCH §Codex JSONL Schema bullet 3). This is the only legitimate use of a parsed timestamp in adapter code; the `no_walltime_in_adapter.rs` grep forbids `Timestamp::now()` but allows arithmetic on parsed timestamps.
- Parser walks JSONL line-by-line, keeping the latest line whose `payload.type=="token_count"` AND `rate_limits` is Some AND at least one of `primary`/`secondary` is Some. If no such line exists in the file → `ProviderError::SchemaDrift { missing: vec!["rate_limits".to_string()] }`.

Future-proofing note: keep the parser strictly typed as `RateLimits { primary: Option<RateLimitTier>, secondary: Option<RateLimitTier> }` for Phase 2 (matches verified upstream). Add a `// TODO Phase 3: consider BTreeMap<String, RateLimitTier> if upstream adds 'weekly'` comment in `jsonl.rs`. Do NOT refactor to BTreeMap in Phase 2.
</verified_codex_rollout_schema>

<spawn_blocking_pattern>
<!-- From RESEARCH §spawn_blocking Pattern (narrow scope per Claude's Discretion #4). -->

Wrap ONLY the sync IO segment (rusqlite open + busy_timeout + JSONL scan IO + parse) in `tokio::task::spawn_blocking`. Keep async-layer concerns (path discovery, error mapping) outside the closure.

Required closure shape: `move + 'static` capturing owned `PathBuf` + owned `Vec<PathBuf>` + `Copy` `jiff::Timestamp`. JoinError mapping in async layer distinguishes `je.is_panic()` (yields `ProviderError::Internal { source: anyhow::anyhow!("codex adapter blocking thread panicked") }`) from other JoinError variants.

In Phase 2, the SQLite portion is intentionally minimal: open with `OpenFlags::SQLITE_OPEN_READ_ONLY | OpenFlags::SQLITE_OPEN_NO_MUTEX`, call `busy_timeout(Duration::from_millis(250))`, then `drop(conn)`. Do NOT run any `SELECT` (RESEARCH §Codex SQLite Schema recommendation — defer `threads` table reads to Phase 3). The contract (D-45 "supplemental metadata") is honored by the existence of the read-only-open code path; surfacing actual row data is not a Phase 2 deliverable.
</spawn_blocking_pattern>
