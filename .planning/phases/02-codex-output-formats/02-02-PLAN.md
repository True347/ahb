## Deviation from CONTEXT.md D-54 (additive `HpWindow.detailed_label` instead of renaming `windows[0].label`)

**What CONTEXT.md D-54 implied:** "Rename ClaudeProvider's `windows[0].label` from `claude` to `5h` so detailed mode shows indented `5h` / `weekly` row labels."

**What this plan does instead:** Introduce an **additive** field `HpWindow.detailed_label: Option<Cow<'static, str>>` (default `None`, serde-skipped when None). ClaudeProvider sets `windows[0].detailed_label = Some(Cow::Borrowed("5h"))` and `windows[1].detailed_label = Some(Cow::Borrowed("weekly"))`. The detailed-mode renderer reads `w.detailed_label.as_deref().unwrap_or(&w.label)` per row. The compact-mode renderer (`compact_line_colored`) stays UNCHANGED and continues to use `windows[0].label` as the prefix.

**Why this deviation is required (and gets adopted, NOT a scope reduction):**

The naive D-54 interpretation breaks TWO previously-LOCKED literals from earlier phases:

1. **Phase 0 D-25 (LOCKED):** MockProvider compact line is `mock-session  ██████░░░░ 60% • resets in 2h00m`. The `mock-session` prefix comes from `windows[0].label` = `Cow::Borrowed("mock-session")`. If compact mode is shifted to use a different label source (e.g. `id_label(state.id)` = `"mock"`), the prefix changes from `mock-session` to `mock` — a silent Phase 0 regression.

2. **Phase 1 (LOCKED compact literal):** `tests/cli_walking_skeleton.rs::ahb_default_run_emits_one_claude_row_with_real_numbers` asserts `^claude  \\S{10}…` (regex). Currently ClaudeProvider sets `windows[0].label = Cow::Borrowed("claude")`. If we rename windows[0].label to `"5h"`, this regex still matches because `id_label(Claude) == "claude"` would be the new prefix source — BUT only if we ALSO mutate `compact_line_colored` to use `id_label` instead of `windows[0].label`. That mutation breaks Phase 0 D-25 per (1) above. The two are coupled.

**Net behavior change vs CONTEXT.md D-54:** None at the user-visible compact level. The detailed-mode UI exactly matches D-53's example output (header line `claude` + indented `5h` and `weekly` rows). The only delta is in the `--json` schema (D-52 additive policy applies):

- `windows[].detailed_label` is now a possible field in the JSON output (omitted when None per `#[serde(skip_serializing_if = "Option::is_none")]`).
- For ClaudeProvider, the JSON shape gains `"detailed_label": "5h"` on `windows[0]` and `"detailed_label": "weekly"` on `windows[1]` (where today there's only `"label": "claude"`).
- For CodexProvider, MockProvider, etc., the field is omitted (None), so their JSON shape is unchanged.
- Per D-52 schema_version policy: "新增 `JsonWindow` 欄位 → 消費者必須 tolerate unknown fields" — this is an additive change that does NOT bump schema_version.

**Note for Plan 02-03 (--json):** `JsonWindow` should mirror this additive field as `pub detailed_label: Option<String>` with `#[serde(skip_serializing_if = "Option::is_none")]`. Plan 02-03 will add this to the DTO; the round-trip stays clean.

**Source of truth for future planners:** This block, plus the corresponding rendered diff in `01-UI-SPEC.md` Phase 2 amendment (Plan 02-01 already lands the sentinel-amendment block; the detailed-label decision is captured here in the PLAN since it does not modify a UI literal — it adds a per-row data field).

<iso_week_anchor_pattern>
Per RESEARCH §Claude Weekly Limit Handling (lines 414-425). Compute the next Monday 00:00 in the host's local timezone as a UTC jiff::Timestamp:

Algorithm (pseudocode — verify exact jiff 0.2 API names via Context7 during impl):
1. let zoned = now.to_zoned(jiff::tz::TimeZone::system())
2. let civil = zoned.date()
3. let weekday_one_based = civil.weekday().to_monday_one_offset()   // 1=Mon..7=Sun (or use the API jiff actually provides; the math is "days_until_next_monday is 7 when today is Monday, else 8 - weekday")
4. let days_until_next_monday = if weekday_one_based == 1 { 7 } else { 8 - i64::from(weekday_one_based) }
5. let next_monday_date = civil.checked_add(jiff::civil::Span::new().days(days_until_next_monday)).ok()?
6. let monday_midnight = next_monday_date.at(0, 0, 0, 0).to_zoned(jiff::tz::TimeZone::system()).ok()?
7. Some(monday_midnight.timestamp())

pub fn compute_weekly_window(sorted_msgs: &amp;[AssistantEntry], now: jiff::Timestamp) -> Option&lt;HpWindow&gt; {
    let reset_at = next_iso_week_anchor(now)?;
    let week_start = reset_at.checked_sub(jiff::Span::new().days(7)).ok()?;
    let used_tokens: u64 = sorted_msgs.iter()
        .filter(|m| m.timestamp &gt;= week_start &amp;&amp; m.timestamp &lt;= now)
        .map(|m| m.message.usage.as_ref().map_or(0_u64, |u| u.cache_creation_input_tokens))
        .sum();
    let percent = match CLAUDE_WEEKLY_TOKEN_LIMIT {
        Some(limit) =&gt; percent_remaining(used_tokens, limit),
        None =&gt; f32::NAN,   // sentinel: render layer paints `??%`
    };
    Some(HpWindow {
        label: Cow::Borrowed("weekly"),
        percent_remaining: percent,
        reset: ResetInfo { resets_at: reset_at },
        bar_color: None,
        detailed_label: Some(Cow::Borrowed("weekly")),
    })
}

The renderer must handle f32::NAN. This is visually distinct from the SchemaDrift sentinel ("out-of-date" wording) — the data isn't drifted, the limit estimate is just unavailable.

#[inline]
fn effective_label(w: &amp;HpWindow) -&gt; &amp;str {
    w.detailed_label.as_deref().unwrap_or(&amp;w.label)
}

pub(crate) fn detailed_block(state: &amp;ProviderState, now: &amp;jiff::Timestamp, ascii: bool, color_on: bool) -&gt; String {
    let mut out = String::new();
    out.push_str(id_label(state.id));   // header line
    out.push('\\n');
    let label_width = state.windows.iter().map(|w| effective_label(w).len()).max().unwrap_or(0);
    for (i, w) in state.windows.iter().enumerate() {
        let line = render_window_row(w, now, ascii, color_on, label_width);
        out.push_str("  ");              // 2-space indent per D-53
        out.push_str(&amp;line);
        if i + 1 &lt; state.windows.len() { out.push('\\n'); }
    }
    out
}

fn render_window_row(w: &amp;HpWindow, now: &amp;jiff::Timestamp, ascii: bool, color_on: bool, label_width: usize) -&gt; String {
    let label_padded = format!("{:&lt;width$}", effective_label(w), width = label_width);
    let countdown = format_countdown(now, &amp;w.reset.resets_at);
    let sep = if ascii { '|' } else { '\\u{2022}' };
    if w.percent_remaining.is_nan() {
        // limit-unknown rendering (distinct from SchemaDrift "out-of-date").
        let bar = "\\u{2592}".repeat(BAR_WIDTH);
        return format!("{label_padded}  {bar} ??% {sep} resets in {countdown} (limit unknown)");
    }
    // Otherwise mirror the compact bar build (pct clamp + filled_cells + glyph selection + color match).
    let pct = w.percent_remaining.clamp(0.0, 100.0);
    let filled = filled_cells(pct);
    let (filled_glyph, empty_glyph) = if ascii { ("#", "-") } else { ("\\u{2588}", "\\u{2591}") };
    let filled_str = filled_glyph.repeat(filled);
    let empty_str = empty_glyph.repeat(BAR_WIDTH - filled);
    let bar = if color_on {
        match pct {
            p if p &gt;= 30.0 =&gt; format!("{}{}", filled_str.green(), empty_str.bright_black()),
            p if p &gt;= 10.0 =&gt; format!("{}{}", filled_str.yellow(), empty_str.bright_black()),
            _ =&gt; format!("{}{}", filled_str.red(), empty_str.bright_black()),
        }
    } else {
        format!("{filled_str}{empty_str}")
    };
    format!("{label_padded}  {bar} {pct_int}% {sep} resets in {countdown}", pct_int = pct.round() as u32)
}
