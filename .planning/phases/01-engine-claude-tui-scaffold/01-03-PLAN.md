## ratatui 0.30 API — Context7-VERIFIED (WARNING #4 resolution)

The planner verified the exact `ratatui::run` signature via `docs.rs/ratatui/0.30.0` (Context7-equivalent lookup). The signature is SYNCHRONOUS:

```rust
// From docs.rs/ratatui/0.30.0/src/ratatui/init.rs:
pub fn run<F, R>(f: F) -> R
where
    F: FnOnce(&mut DefaultTerminal) -> R,
{
    let mut terminal = init();      // init() internally calls try_init() which calls set_panic_hook()
    let result = f(&mut terminal);
    restore();
    result
}
```

**Implications LOCKED for the executor (do NOT re-discover):**

1. `ratatui::run` is SYNC — the closure cannot be `async fn` directly.
2. The panic hook IS auto-installed by `init()` (called by `run`) — Pitfall L2 guidance is preserved.
3. To drive a tokio async event loop INSIDE the sync closure, use the spawn_blocking → block_on bridge:
   ```
   pub async fn run(engine: Engine) -> anyhow::Result<()> {
       if !std::io::stdout().is_terminal() { eprintln!(...); std::process::exit(2); }
       let handle = tokio::runtime::Handle::current();
       tokio::task::spawn_blocking(move || -> anyhow::Result<()> {
           ratatui::run(|terminal: &mut ratatui::DefaultTerminal| -> anyhow::Result<()> {
               handle.block_on(async move {
                   // async select! loop here — events / fetch_tick / render_tick
                   Ok(())
               })
           })
       }).await??;
       Ok(())
   }
   ```
4. **Forbidden alternative:** `ratatui::init() + restore()` pair — Pitfall L2 + grep gate. `init()` alone DOES install a panic hook (per source inspection), but the manual pattern requires hand-composing the restore-on-?-early-return logic and is more fragile than `run()`. Use `run()`.
5. `EventStream` async-readability: `ratatui::crossterm::event::EventStream::new()` returns a `Stream`; consuming `.next().await` requires the `futures_util::StreamExt` trait in scope. Cargo.toml decision: ADD `futures-util = { version = "0.3", default-features = false, features = ["std"] }` as a prod dep with phase comment `# Phase 1 — TUI EventStream consumption (TUI-01); StreamExt::next for tokio::select!`.
