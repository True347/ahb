# Phase 1 — UI Design Contract

> Visual and interaction contract for AHB's two terminal surfaces (CLI compact line + TUI fixed view). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Form factor note:** AHB is a terminal-only tool (Rust CLI + ratatui TUI). Web-design idioms (px sizing, hex color, shadcn registries) are adapted to terminal-native equivalents: **character cells** instead of pixels, **ANSI palette roles** instead of hex, **ratatui widgets** instead of shadcn components. Where a template field is structurally incompatible with terminals, it is marked `not applicable` with the terminal-native equivalent listed alongside.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (Rust terminal app — shadcn does not apply) |
| Preset | not applicable |
| Component library | `ratatui` 0.30 (via `ratatui::crossterm` 0.29 re-export) — locked by STACK.md |
| Icon library | none — Unicode block / shade / bullet glyphs only (`U+2588`, `U+2591`, `U+2022`); emoji deferred to v2 per Phase 0 D-19 |

**Source:** Phase 0 D-15 / D-16 / D-18 / D-19 (`.planning/phases/00-spike-spine/00-CONTEXT.md`) + STACK.md (`ratatui` 0.30 + `crossterm` 0.29 + `owo-colors` 4 locked).

## Spacing Scale

AHB renders into character cells, not pixels. The "spacing scale" is the **column-cell layout grammar** for one HP-bar row. Every value below is a count of monospace columns / rows — the terminal equivalent of a 4px grid.

| Token | Value | Usage |
|-------|-------|-------|
| inline-gap-sm | 1 col | Gap between `%` and bullet (`U+2022`), between bullet and `resets in`, between countdown and any trailing field |
| inline-gap-md | 2 cols | Gap between provider label and the bar (locked in `render_text.rs`: `"{label}  {bar}"`) — distinguishes the label column from the bar column at a glance |
| bar-width | 10 cells | Fixed HP-bar width (Phase 0 D-16) — required for multi-provider vertical alignment in compact mode and for snapshot-test stability |
| row-block-gap | 1 row | Blank row between provider-row groups in `--detailed` (Phase 2) — not used in Phase 1 compact single-row output |
| tui-frame-pad | 1 cell | Border padding inside the TUI altscreen frame (single-cell margin between ratatui's border and the first row of content) |
| tui-row-stride | 1 row | One provider = one row in the TUI body; rows are not separated by blank rows (Phase 1 expects ≤ 3 providers, density wins over breathing room) |

**Exceptions:** none. The bar is fixed-width; the label column is naturally variable-width (provider name length) but is left-aligned with a single inline-gap-md separator — no padding-to-column-N alignment in Phase 1 (Phase 2 `--detailed` will revisit).

**Source:** Phase 0 D-16 (bar-width=10 locked), `render_text.rs` lines 50–56 (label gap=2 cols locked), `compact_line()` literal `"{label}  {bar} {pct}% {sep} resets in {countdown}"`.

## Typography

AHB cannot pick font sizes — the terminal owns that. The typographic contract is the **text-intensity ramp** (the terminal equivalent of font weight + size) plus the **glyph-set policy** (which Unicode codepoints are allowed in output).

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | terminal default (1 cell tall) | Normal / Reset intensity | 1 row (terminal-native) |
| Bar fill | terminal default | Normal intensity, colored (see Color section) | 1 row |
| Reset countdown | terminal default | Normal intensity, dim modifier OFF (must remain legible at a glance — this is the second most-glanced field after the bar) | 1 row |
| Error / sentinel | terminal default | Bold ON for the leading word ("ERROR" / "out-of-date") so it visually outranks healthy rows even in a 3-row stack; rest of the row is normal intensity | 1 row |

**Glyph-set policy (Unicode codepoints permitted in Phase 1 output):**

| Codepoint | Char | Role | Source |
|-----------|------|------|--------|
| U+2588 | `█` | HP-bar filled cell (Unicode mode) | Phase 0 D-15 |
| U+2591 | `░` | HP-bar empty cell (Unicode mode) | Phase 0 D-15 |
| U+2022 | `•` | Separator between `%` and `resets in` (Unicode mode) | Phase 0 D-25 |
| `#` | `#` | HP-bar filled cell (ASCII mode, `--ascii`) | Phase 0 D-18 |
| `-` | `-` | HP-bar empty cell (ASCII mode, `--ascii`) | Phase 0 D-18 |
| `|` | `|` | Separator (ASCII mode, `--ascii`) | Phase 0 D-18 |
| U+0020 – U+007E | ASCII printable | All text content (labels, percent, countdown, error messages) | Phase 0 D-19 (no emoji) |

**Banned in Phase 1:**

- Emoji (any U+1F000+ codepoint) — Phase 0 D-19, deferred to v2 DIFF-01
- Box-drawing characters U+2500–U+257F **outside ratatui's own border rendering** — direct usage forbidden; let ratatui's `Block::default().borders(Borders::ALL)` draw them so they survive the crossterm version we re-export
- Replacement char U+FFFD — must NEVER appear; if it does, the charset-fallback path failed and the bug must be fixed, not displayed

**Source:** Phase 0 D-15 / D-18 / D-19, `GEMINI_SPIKE.md` Charset Verification section (byte-proof of the U+2588 / U+2591 / U+2022 round-trip on kitty), `render_text.rs` test `unicode_bytes_present`.

## Color

Terminal apps cannot use hex. AHB's color contract is expressed in **ratatui's `Color` enum + ANSI 16-color palette** (the only subset guaranteed to survive every realistic terminal — `xterm-256color`, tmux, Windows Terminal, plus user-customized palettes that remap basic ANSI). Hex equivalents are listed for the checker's 60/30/10 reasoning, but the **binding identifier is the ANSI role**, not the hex.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `Color::Reset` (terminal default fg/bg — typically near-white on near-black or vice versa) | Provider labels, percent number, "resets in" prose, countdown digits, error message body. Every text field that is NOT the bar fill, NOT a status keyword. |
| Secondary (30%) | `Color::DarkGray` (ANSI `90`) | Bar **empty cells** (`░` / `-`), `•` / `|` separator, stale-cache indicator suffix `"(stale Ns ago)"` (Phase 3 reuses), background scaffolding in TUI border. Visually present but recessive. |
| Accent (10%) | `Color::Green` (healthy) → `Color::Yellow` (warn) → `Color::Red` (critical), single ramp | Bar **filled cells only** (`█` / `#`). Color thresholds: `Green` when `percent_remaining ≥ 30.0`, `Yellow` when `10.0 ≤ percent < 30.0`, `Red` when `percent < 10.0`. The `BarColor` enum in `model.rs` (Red/Yellow/Green) is the adapter's *hint*; if `bar_color: Some(_)` it overrides the percent-based default, otherwise the renderer derives from `percent_remaining`. |
| Destructive | `Color::Red` + Bold | Reserved for the leading word of error rows (`ERROR`) and the schema-drift sentinel (`out-of-date`). NOT used for bar fill at low percent — those use the accent ramp Red without Bold to keep the two semantic uses distinguishable side-by-side. |

**Accent reserved for** (exhaustive — anything not on this list MUST use Dominant or Secondary):

1. The filled cells of the HP bar (`█` / `#`)
2. The leading word of an error row (`ERROR`) — uses Destructive (Red + Bold)
3. The leading phrase of the schema-drift sentinel (`Claude adapter may be out-of-date`) — uses Destructive (Red + Bold)

**Color-off paths (must produce zero ANSI escape bytes):**

- `stdout` is not a TTY (`std::io::IsTerminal::is_terminal(&io::stdout()) == false`) — CORE-05, Phase 0 D-17
- `NO_COLOR` env var is set (any value) — Phase 0 D-17
- `--color=never` flag — Phase 0 D-17
- `--json` output — always uncolored regardless of TTY (Phase 0 D-17 explicit)

When color is off, the bar still renders — same glyphs, same width, no escape sequences. The visual fallback for "low percent" in colorless mode is the **glyph count itself** (a 1-cell bar is obviously low), not any text marker.

**`--color=always` path:** emits ANSI escapes even when piped. Use case: piping into `less -R` or recording into a styled log.

**TUI color (`AHB tui`):** ratatui ALWAYS runs in altscreen → always a TTY → always colored. The `NO_COLOR` / `--color=never` paths are CLI-only; the TUI ignores them (this is the documented terminal-app convention; the TUI is a "rich" surface by definition).

**Source:** Phase 0 D-17 (color/NO_COLOR/--color), STACK.md (`owo-colors` 4 with `supports-colors` feature is the chosen color crate; in TUI path, ratatui's own `Style::default().fg(Color::Green)` is the channel — do not pull `owo-colors` into the TUI render path, two coloring crates in one process invite double-escape bugs).

## Copywriting Contract

AHB is operator-facing. Every string is short, imperative, and tells the user what's true RIGHT NOW or what to do next. No marketing voice. No exclamation marks. No "Oops!" / "Uh oh!" — those are app-store voice and they erode trust in a status tool. Lowercase for state words (`session`, `weekly`, `stale`) — uppercase reserved for status keywords the user is meant to scan-find (`ERROR`).

| Element | Copy |
|---------|------|
| Primary CTA | **N/A — AHB has no CTAs.** This is a read-only status tool. The user "action" is running the binary; there are no buttons, prompts, or modal confirmations. The closest equivalent is the help line surfaced by `clap`: `AHB — AI HP Bar — multi-CLI subscription session usage at a glance` (already locked in `main.rs` `#[command(about = ...)]` and `Cargo.toml` `description`). |
| Empty state heading | `no providers configured` |
| Empty state body | `add at least one provider to ~/.config/ahb/config.toml — see README` (printed when the resolved provider list is empty after applying CFG-04 skip-unconfigured filter; exit code 0, not an error) |
| Error state (per-row, healthy peers present) | `{provider}  ERROR: {one-line reason}` — example: `claude  ERROR: ~/.claude/projects not found — is Claude Code installed?`. The reason line MUST be a single line ≤ 80 cols and MUST end with a "next step" hint (a question the user can act on or a path to check). |
| Error state (all providers failed) | Same per-row format for each; process exits with code 1 (Phase 2 CORE-06 locks the exit code; Phase 1 already emits the per-row text correctly so Phase 2 only needs to add the exit-code wiring). |
| Schema-drift sentinel (ADP-03) | `claude  ▒▒▒▒▒▒▒▒▒▒ ??% • Claude adapter may be out-of-date` — bar renders all-empty cells in DarkGray (not Red — this is "unknown", not "critical"), percent shown as literal `??`, separator and message follow. The leading 6 words `Claude adapter may be out-of-date` are Bold + Red (Destructive role). |
| TUI non-TTY refusal (TUI-05) | `AHB tui requires a terminal (stdout is not a TTY). Run AHB without 'tui' for piped / non-interactive output.` — printed to stderr, exit code 2. |
| TUI quit hint (status line, footer row) | `q quit  ·  ctrl-c quit` — single line, Secondary color, bottom row of the TUI frame. No "press any key to..." prose. |
| Destructive confirmation | **N/A — Phase 1 has no destructive actions.** AHB only reads (Claude JSONL files, keyring entries). It never writes secrets back to keyring in Phase 1 (Phase 2 / 3 may add `AHB login` style commands; those will declare their own confirmation copy). |

**Tone rules (binding):**

- Lowercase for nouns and prose (`provider`, `session`, `terminal`).
- Uppercase ONLY for status keywords the user scan-finds: `ERROR`. (No `WARNING`, no `INFO` — Phase 1 only has healthy / error / out-of-date; the third uses prose, not a keyword.)
- No emoji, no exclamation marks, no "Oops" / "Uh oh".
- Error messages MUST end with a next-step hint — "is X installed?", "see README", "check ~/.config/...". No bare error reasons like `"file not found"`.
- Provider labels in output use the lowercase provider name as it appears in `ProviderId`'s `snake_case` serialization (`claude`, `codex`, `gemini`, `mock`) — NEVER capitalized, NEVER `Claude` / `Claude Code` / branded form. This is for vertical alignment AND for staying clear of provider trademark touchiness.

## Layout & Interaction Contract

> Templated 60/30/10 + tokens above describe atoms. The contract below describes molecules — the exact compositions Phase 1 must ship. This section is the executor's render-path source of truth.

### CLI compact-line layout (Phase 1 default `AHB` output)

One physical row per provider, vertically aligned by virtue of the fixed bar width. Format string (already locked in `render_text.rs::compact_line` for Phase 0; Phase 1 extends to N rows + color):

```
{label}␣␣{bar}␣{pct}%␣{sep}␣resets␣in␣{countdown}
```

Where:
- `label` = lowercase provider name from `ProviderId` (e.g., `claude`, `codex`, `mock`)
- `bar` = exactly 10 chars: `filled_count` copies of `█` (or `#`) + `(10 - filled_count)` copies of `░` (or `-`)
- `pct` = integer 0..=100 (rounded from `percent_remaining`), no leading zeros, no fractional digits
- `sep` = `•` (Unicode mode) or `|` (ASCII mode)
- `countdown` = `Xh00m` format from `format_countdown()` — hours unpadded, minutes always 2-digit zero-padded; negative or unrepresentable spans clamp to `0h00m`

Multi-provider example (3 rows, Unicode + color):

```
claude   ████████░░ 80% • resets in 4h15m
codex    ██████░░░░ 60% • resets in 2h00m
gemini   ERROR: gemini.google.com unreachable — check network
```

The third row demonstrates the error-row contract: same `{label}␣␣` prefix, no bar (the bar slot is replaced by `ERROR: …`), no `resets in` clause. The label column width is determined by the widest configured provider label, padded with spaces — labels left-align, bars left-align relative to each other.

### TUI fixed-view layout (`AHB tui`)

Single ratatui `Frame` per refresh tick (15s default per TUI-02), no scrolling, no panels.

```
┌─ AHB ────────────────────────────────────────────────────┐
│                                                          │
│  claude   ████████░░ 80% • resets in 4h15m               │
│  codex    ██████░░░░ 60% • resets in 2h00m               │
│  gemini   ERROR: gemini.google.com unreachable           │
│                                                          │
│  q quit  ·  ctrl-c quit                                  │
└──────────────────────────────────────────────────────────┘
```

- Border: `Block::default().title(" AHB ").borders(Borders::ALL)` — ratatui draws the border using its bundled crossterm 0.29 (the `ratatui::crossterm` re-export); we do NOT add `crossterm` directly to `Cargo.toml` (STACK.md "What NOT to use" — double-crossterm hazard).
- Inner layout: `Layout::vertical([Constraint::Length(1), Constraint::Min(providers_len as u16), Constraint::Length(1), Constraint::Length(1)])` — top pad, provider rows, footer-pad, quit-hint row.
- Provider rows: each row is one `Line` built from ratatui `Span`s — `Span::raw(label_padded)`, `Span::styled(filled_cells, Style::default().fg(accent_color))`, `Span::styled(empty_cells, Style::default().fg(Color::DarkGray))`, etc.
- Quit hint row: `Color::DarkGray` (Secondary), centered or left-aligned at single inline-gap-md indent (executor's discretion within Secondary color budget).

### Interaction contract (TUI input handling)

| Input | Action | Recovery |
|-------|--------|----------|
| `q` (any modifier) | Quit cleanly | `ratatui::restore()` runs via Drop / panic-hook chain; terminal returns to mainscreen, cursor visible, raw mode off |
| `Ctrl-C` (`KeyCode::Char('c') + KeyModifiers::CONTROL`) | Quit cleanly (same path as `q`) | Same as above. Does NOT raise SIGINT to the parent shell — TUI consumes the keystroke. |
| Any other key | Ignored (no-op) | — |
| Terminal resize | ratatui auto-handles via its event loop; layout re-flows on next draw | — |
| Panic in any code path | `ratatui::init()`'s panic hook (which we wrap around our Phase 0 stderr-print hook per D-27) restores the terminal FIRST, then prints `ahb panicked: {info}` to stderr, then calls the default hook | TUI-04: verified by integration test that injects `panic!()` and asserts the parent shell is not left in raw / altscreen mode |
| Adapter `panic!()` during refresh tick | The fetch loop wraps each provider in `tokio::task::spawn(...)` + `.await` returning `Result<Result<ProviderState, ProviderError>, JoinError>`; a `JoinError::is_panic()` is converted to a Phase-1-internal `ProviderError::Internal(anyhow!("adapter panicked"))` and rendered as a normal error row | ADP-01: the tool never crashes because one adapter panicked |

### Refresh-tick contract (TUI-02)

- Default tick: 15 seconds (Phase 1 hardcoded; Phase 3 TUI-03 makes it config-driven)
- Implementation: `tokio::time::interval(Duration::from_secs(15))` running on `current_thread` runtime (already configured in `main.rs`); each tick triggers a re-render. Per-provider fetch results are independent — a slow provider does not block the next tick (`spawn` + `select!` over the providers).
- Re-render is full-frame (ratatui's immediate-mode model); no partial-update logic in Phase 1.
- The countdown text recomputes on each tick from `(jiff::Timestamp::now() - resets_at)` — does NOT require a fresh fetch; the engine caches `ProviderState` between fetches (Phase 3 elevates this to moka).
